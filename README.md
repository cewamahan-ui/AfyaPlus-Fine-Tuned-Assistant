# AfyaPlus Fine-Tuned Assistant

## Overview
A LLaMA 3.1 8B model fine-tuned with QLoRA on curated AfyaPlus operational
data: appointment workflows, triage escalation signposting, patient
registration, and system/user access management for a community health
platform serving peri-urban Kenya. The model is strictly non-diagnostic —
it flags, escalates, and documents, but never diagnoses, prescribes, or
overrides a clinician's judgement.

## Project Structure
- `data/`: `afyaplus_seed.jsonl` (starter curated set, 20 examples), `afyaplus_full.jsonl` (expanded 101 examples), `train.jsonl`, `val.jsonl`, `test.jsonl` (generated by `data_prep.py`)
- `scripts/data_prep.py`: validation + 80/10/10 split
- `scripts/fine_tune.py`: QLoRA training script
- `scripts/merge_model.py`: adapter merge into a standalone checkpoint
- `scripts/local_inference.py`: inference pipeline with safety/disclaimer gate
- `scripts/evaluate_models.py`: base vs fine-tuned evaluation, writes `comparison_results.csv`
- `curation_note.md`: sourcing, quality/safety criteria, coverage gaps
- `memo.md`: one-page stakeholder recommendation

## Disclaimer
This model provides non-diagnostic operational guidance only for community
health workflows (scheduling, registration, escalation, access). It does
not diagnose conditions, prescribe or recommend medication, or make
binding clinical decisions. All clinical judgement remains with a
qualified health provider. Danger signs are escalated per Kenya MOH
community health protocols, not resolved by the assistant.
